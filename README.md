## 📌 About

**Nuke-tool** is a Python-based Discord project created for educational purposes and for learning about Discord bot development, asynchronous programming, command handling, and server administration concepts.

The project includes a console-driven interface and a collection of experimental tools. Some operations represented by the original prototype can make major changes to a Discord server. They are documented here as potentially destructive behaviours—not as recommended actions or instructions to execute them.

> ⚠️ **EDUCATIONAL PURPOSE ONLY — USE AT YOUR OWN RISK**
>
> This project is intended strictly for educational purposes, learning, and controlled testing. Use Discord bots and administrative features only in servers where you have explicit permission from the server owner. Never use this project to disrupt, damage, spam, harass, or access any server or user without authorization.
>
> The developer is not responsible for misuse, data loss, server disruption, account actions, or violations of Discord's Terms of Service.

## 📋 Requirements

Before setting up the project, make sure you have:

- Python 3 installed.
- pip package manager.
- A Discord account for development.
- A private test server that you own or are authorized to manage.
- Basic knowledge of Python and Discord bot permissions.

## 🚀 Installation

### 1. Clone the repository

```bash
git clone https://github.com/dcsoumen87-blip/Nuke-tool.git
```

### 2. Open the project folder

```bash
cd Nuke-tool
```

### 3. Install dependencies

```bash
pip install discord.py aioconsole
```

### 4. Review the source code

Read and understand the code before running anything. Do not run unreviewed or destructive operations on a real Discord server.

## ⚙️ Configuration & Permissions

If you are developing or testing a Discord bot:

1. Create an application in the Discord Developer Portal.
2. Create a bot for your application.
3. Keep the bot token private.
4. Never publish tokens, passwords, or other secrets in a public repository.
5. Use a private test server that you control.
6. Grant only the minimum permissions required for the specific safe test.
7. Review the current Discord Developer Terms and Developer Policy before deploying a bot.

**Security note:** Never paste your bot token into public chats, screenshots, source files, or commits. If a token is exposed, reset it immediately through the Discord Developer Portal.

---

## 🧪 Safe Testing Guidelines

For responsible learning and testing:

- Use a private development server.
- Obtain explicit permission before testing any server-management feature.
- Use mock data or a local simulation wherever possible.
- Avoid mass actions and irreversible changes.
- Do not send unsolicited bulk messages.
- Do not create spam, raids, or service disruption.
- Keep backups of any test data.
- Stop testing immediately if an unexpected action occurs.

---

## 🛡️ Responsible Use

This repository is provided for code study and educational experimentation. A feature being present in a prototype does not mean it is safe, approved, or appropriate to use.

The project should not be used for:

- Unauthorized server destruction or disruption.
- Raids, spam, harassment, or mass unsolicited messaging.
- Unauthorized moderation actions.
- Circumventing Discord limits, safeguards, or platform policies.
- Accessing or modifying servers without permission.

The recommended direction for further development is to replace risky operations with dry-run previews, mock events, explicit confirmations, permission checks, audit logging, and reversible test actions.
